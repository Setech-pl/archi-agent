# Archi Agent v0.3.0-alpha.1

**Status:** prerelease candidate; the owner reported smoke **PASS** for the exact integration VSIX on 2026-09-29. Git tag and GitHub prerelease publication are pending.

## Highlights since v0.2.0-alpha.1

- **Reviewed Sequence:** Generate Diagram → Sequence uses a bounded plan, local validation, deterministic PlantUML rendering, and an independent semantic reviewer. S1 owner smoke passed with Ollama on 2026-09-23. The older Generate Sequence Diagram command remains a separate compatibility path.
- **UX1 navigation:** Archi Agent: Open presents Generate Diagram, Configuration, Knowledge Management, and Convert to Markdown. UX1 owner smoke passed on 2026-09-23.
- **Local conversion:** text-layer PDF, DOCX, and XLSX convert to one unsaved Markdown editor without a model, network request, Knowledge Pack, or source modification. Cancel and errors open no partial result.
- **D2 Component:** Generate Diagram → Component uses its own grounded plan, local validator, deterministic renderer, and independent review. D2 owner smoke passed on 2026-09-28.
- **Provider profiles:** LM Studio and Ollama use loopback OpenAI-compatible endpoints. Anthropic, OpenAI, and OpenRouter use fixed HTTPS endpoints and VS Code SecretStorage for keys. Automated tests cover the adapters; live owner smoke has not covered every profile or paid cloud calls.

## Install and upgrade

After publication, download **archi-agent-0.3.0-alpha.1.vsix** and **archi-agent-0.3.0-alpha.1.sha256** from the [v0.3.0-alpha.1 prerelease page](https://github.com/Setech-pl/archi-agent/releases/tag/v0.3.0-alpha.1). Check the VSIX against the SHA-256 file, then in VS Code choose **Extensions → … → Install from VSIX…**. The VSIX includes its runtime and conversion worker; users need no repository checkout, npm, separate Node.js installation, or Archi Agent backend.

Existing LM Studio settings remain compatible until an explicit provider profile is selected. After upgrade, use **Archi Agent: Open → Configuration** to select a profile and model. Cloud profiles also need a provider-specific API key entered through **Set or Update API Key**. Profile and model choices are machine scoped; keys remain in VS Code SecretStorage. A selected model is bound to its profile. No migration of Knowledge Pack files is required.

For diagrams, set **archiAgent.knowledgePackPath** to the absolute path of a local directory containing exactly **systems.md**, **actors.md**, **relationships.md**, **aliases.md**, and **rules.md** in the [documented format](../knowledge-pack-format.md). A structured-output capable model is required. Choose Sequence or Component, then provide an active flow document, flow file, or typed description. Verified results open as unsaved PlantUML and grounding-report editors; save them manually. Conversion can be run independently from **Convert to Markdown**.

## Known limits and deferred milestones

- Diagram generation uses one local Knowledge Pack directory. The extension does not automatically save or version generated editors. The PlantUML editor has no built-in preview.
- Reviewed generation may offer a clearly marked unverified candidate after local checks when semantic review rejects or fails; it has no grounding report. There is no retry, repair, or provider fallback.
- PDF conversion extracts text, not layout or scanned-image OCR. DOCX complex layout and merged cells may lose fidelity. XLSX uses saved formula results without recalculation. Conversion is bounded by input, output, archive, page, sheet, cell, and time limits; see [extension limits](../vscode-extension.md#known-limitations). DOC and XLS are unsupported.
- MCP (M1), VS Code Chat (C1), C4 and ArchiMate diagrams (D3–D5), Knowledge Pack Builder extraction and evidence verification (K2), its UI and write flow (K3), Enterprise Architect integration, and marketplace publishing are not part of this prerelease. The internal deterministic Builder Stage A core is implemented but is not exposed by the VSIX. Conversion does not make documents into a Knowledge Pack or automatic diagram source.

See the [root README](../../README.md) and [extension guide](../vscode-extension.md) for a first-run walkthrough.
